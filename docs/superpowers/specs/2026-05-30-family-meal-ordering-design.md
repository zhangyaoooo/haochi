# 家庭点餐微信小程序 — 设计文档

**日期**: 2026-05-30  
**状态**: 待评审

---

## 1. 项目概述

一个面向单家庭内部使用的微信小程序，家庭成员可以从自建菜谱库中点餐（今天 / 明天），
其他成员认领烹饪任务，完成后给予评价。

### 核心约束

- **单家庭私有**：仅供一个家庭使用，首次进入需输入密码 `33066`
- **全员平等**：所有成员权限一致，无角色区分
- **菜谱自建**：菜谱完全由家庭成员录入，无系统预置

---

## 2. 技术架构

```
微信小程序（前端）
    ↕
微信云开发（后端）
  ├── 云函数    → 业务逻辑
  ├── 云数据库  → NoSQL 文档型存储
  └── 云存储    → 菜谱成品图
```

选型理由：场景数据量小（单家庭），微信云开发免费额度足够；免运维；原生集成体验好。

## 4. 数据模型

### 4.1 用户 `users`

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 自动生成 |
| `openid` | string | 微信 openid，唯一标识 |
| `nickName` | string | 微信昵称 |
| `avatarUrl` | string | 头像 URL |
| `createdAt` | Date | 加入时间 |

### 4.2 菜谱 `recipes`

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 自动生成 |
| `name` | string | 菜名 |
| `category` | string | 分类标签（如"荤菜""素菜""汤""主食"等） |
| `ingredients` | array | `[{name: string, amount: string}, ...]` |
| `steps` | array | `[{order: number, text: string}, ...]` |
| `cookingTime` | number | 烹饪耗时（分钟） |
| `difficulty` | string | `easy` / `medium` / `hard` |
| `imageUrl` | string | 成品图（云存储 fileID） |
| `createdBy` | string | 创建者 openid |
| `createdAt` | Date | 创建时间 |
| `updatedAt` | Date | 更新时间 |

### 4.3 点单 `orders`

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 自动生成 |
| `recipeId` | string | 关联菜谱 ID |
| `recipeName` | string | 冗余菜名，避免联表查询 |
| `date` | string | `"2026-05-31"` 格式，指定哪一天吃 |
| `orderedBy` | string | 点单人 openid |
| `orderedByName` | string | 冗余点单人昵称 |
| `status` | string | `ordered` → `claimed` → `completed`；可随时变为 `cancelled` |
| `claimedBy` | string | 认领人 openid（status 为 claimed/completed 时有值） |
| `claimedByName` | string | 冗余认领人昵称 |
| `rating` | number | 1-5 星，完成后由点单人评价 |
| `feedback` | string | 评价文字 |
| `createdAt` | Date | 点单时间 |

## 5. 核心流程

### 5.1 首次访问 & 登录

```
打开小程序
  → 检查本地登录态
  → 未登录 → 跳转密码页
  → 输入密码 "33066"
  → 正确 → 获取微信用户信息 → 写入 users 表 → 存储登录态 → 进入主页
  → 错误 → 提示密码错误，可重试
  → 已登录用户再次打开 → 直接进入主页
```

### 5.2 点餐

```
菜谱 Tab → 浏览/筛选/搜索菜谱
  → 点击菜谱 → 详情页（食材、步骤、耗时、难度、成品图）
  → 点击"我想吃"→ 弹出日期选择（今天 / 明天，默认今天）
  → 确认 → 写入 order(status=ordered) → Toast"已点好"
```

- 每人每天可点多道菜
- 同一道菜可被多人点（汇总时显示数量，如"红烧肉 ×2"）

### 5.3 认领烹饪 & 完成

```
餐桌 Tab → 按今天/明天分组查看点单汇总
  → 待做的菜显示"我来做"按钮
  → 点击 → order.status = claimed + claimedBy
  → 做完后点击"做好了"→ order.status = completed
```

### 5.4 评价

```
订单完成后 → 该订单的点单人看到"评价"入口
  → 星级打分 1-5
  → 可选文字反馈
  → 写入 order.rating + feedback
```

### 5.5 取消 & 反悔

- 点单人可取消自己 `status=ordered` 的订单 → 删除 order
- 认领人可放弃 `status=claimed` 的认领 → 退回 `ordered`，清空 claimedBy
- 已完成的订单不可取消

## 6. 云函数清单

| 云函数 | 功能 |
|--------|------|
| `login` | 校验家庭密码，获取用户 openid，写入 users 表 |
| `getRecipes` | 分页查询菜谱列表，支持分类筛选和搜索 |
| `getRecipeDetail` | 查询单个菜谱详情 |
| `createRecipe` | 新增菜谱 |
| `updateRecipe` | 编辑菜谱 |
| `deleteRecipe` | 删除菜谱 |
| `createOrder` | 创建点单 |
| `cancelOrder` | 取消点单 |
| `claimOrder` | 认领烹饪 |
| `unclaimOrder` | 放弃认领 |
| `completeOrder` | 标记完成 |
| `rateOrder` | 评价订单 |
| `getTodayOrders` | 获取指定日期的点单汇总 |
| `getMyOrders` | 获取我的点单/我认领的列表 |
| `getHistoryOrders` | 获取历史已完成订单 |

## 7. 异常处理

| 场景 | 处理方式 |
|------|---------|
| 密码错误 | 提示"密码不对，再试试"，不限制重试次数 |
| 网络异常 | 微信小程序统一错误提示，关键操作（点单/认领）带重试机制 |
| 菜谱被删 | 历史订单中 recipeName 冗余字段保证仍可显示菜名；详情页入口置灰 |
| 并发认领 | 云函数内检查 status 是否为 ordered，已被认领则返回提示 |
| 图片上传失败 | 菜谱创建时图片非必填，可后补 |
| 未登录访问 | 全局路由拦截，未登录一律跳转密码页 |
